
## Different Types of Command-Line Parameters

Today I learned that there are different ways to pass values to a program through the command line.

#### Positional Arguments

Positional arguments are identified by their position in the command.

Example:

```bash
node birthyear.js 22
```

Here, `22` is the first command-line argument and can be accessed using `process.argv[2]`.

#### Named (Long) Flags

Named flags begin with `--` and assign a name to the value.

Example:

```bash
node birthyear.js --age=22
```

I learned that this format is more descriptive because the value is associated with a name. This makes commands easier to read and understand.

#### Short Flags

Short flags begin with a single `-` and are usually an abbreviated form of a longer option.

Example:

```bash
git commit -m "Initial commit"
```

Here, `-m` is a short flag that specifies the commit message.

#### Boolean Flags

Boolean flags do not require a value. They simply enable or disable an option.

Examples:

```bash
node --version
git status --short
```

I learned that these flags change the behavior of a command without requiring additional input.

## Command Line Arguments

Command-line arguments are values passed to a program when it is executed from the terminal.

For example,

```bash
node birthyear.js 22
```

---

## process.argv

`process.argv` stores the command-line arguments in an array.

For example,

```bash
node birthyear.js 22
```
gives 

```text
[
  "node",
  "birthyear.js",
  "22"
]
```

which means

```text
process.argv[0] -> node
process.argv[1] -> birthyear.js
process.argv[2] -> 22
```

Initially, I was confused about why we use `process.argv[2]` instead of `process.argv[0]`.

Then I learned that the first two positions are already occupied by Node.js and the script name, so the first user input always starts from index `2`.

## Why use command-line arguments?

Initially, I used variables like this:

```javascript
let age = 22;
```

Whenever I wanted to test another value, I had to edit the code.

After learning command-line arguments, I realized that I can simply run

```bash
node birthyear.js 30
```

without changing the source code.

This makes the program reusable.

## Command-Line Flags

I also learned another way of passing values using flags.

Example:

```bash
node birthyear.js --age=22
```

Unlike positional arguments, flags give a name to each value.

This makes the command easier to understand, especially when there are many inputs.

For example,

```bash
node student.js --name=Alice --age=20 --department=CSE
```

is much easier to read than

```bash
node student.js Alice 20 CSE
```

because every value has a label.

## Where I got Confusion

When I ran

```bash
node birthyear.js --age=22
```

my program printed

```text
Birth year is : NaN
```

Initially, I thought Node.js was unable to read the argument.

After printing

```javascript
console.log(process.argv[2]);
```

I realized that the program was actually receiving

```text
--age=22
```

instead of

```text
22
```

Since my program was doing

```javascript
Number(process.argv[2])
```

JavaScript tried to convert

```text
--age=22
```

into a number.

This is not a valid number, so it returned `NaN` (Not a Number).

---

## Why do we use split("=")?

This was the part that confused me the most.

I learned that

```text
--age=22
```

is just a string.

The `split()` method divides a string into smaller pieces using a separator.

Example,

```javascript
"--age=22".split("=")
```

returns

```javascript
[
 "--age",
 "22"
]
```

The first element has index `0`.

```text
0 -> --age
```

The second element has index `1`.

```text
1 -> 22
```

Therefore,

```javascript
argument.split("=")[1]
```

returns only

```text
22
```

which can then be converted into a number using

```javascript
Number(...)
```

## One thing I noticed

If I write

```javascript
const age = Number(process.argv[2]);
```

then

```bash
node birthyear.js 22
```

 it works,

but

```bash
node birthyear.js --age=22
```

returns `NaN`.

Similarly, if I write

```javascript
const age = Number(process.argv[2].split("=")[1]);
```
then

```bash
node birthyear.js --age=22
```

works,but

```bash
node birthyear.js 22
```
returns `NaN`.

This helped me understand that the program expects the input to be in the format for which it was written.

## What I Learned Today

- Command-line arguments allow programs to receive input from the terminal.
- `process.argv` stores all command-line arguments.
- User inputs begin at index `2`.
- Flags make commands easier to understand by giving names to values.
- `split()` is used to separate a string into multiple parts.
- `NaN` means "Not a Number" and usually appears when JavaScript cannot convert a value into a number.
