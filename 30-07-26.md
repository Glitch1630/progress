## Functions in JavaScript

Today I learned about functions and why they are used in JavaScript.

A function is a reusable block of code that performs a specific task. Instead of writing the same code multiple times, a function allows me to write it once and call it whenever needed. This makes the code easier to read, maintain, and reuse.

### Function Declaration

A function declaration defines a function using the `function` keyword followed by the function name.

Example:

```javascript
function greet() {
    console.log("Hello World");
}
```

The function is executed by calling it:

```javascript
greet();
```

### Functions with `return`

Initially, I was confused about what `return` actually does.

I thought `return` printed the result, but I learned that it sends the calculated value back to the place where the function was called (the caller).

Example:

```javascript
function add(a, b) {
    return a + b;
}

let result = add(5, 3);
console.log(result);
```

When `add(5, 3)` is executed, the function returns `8`. The function call is replaced by the returned value, so the statement becomes:

```javascript
let result = 8;
```

The variable `result` then stores the value `8`.

I also learned that `console.log()` and `return` are different.

- `console.log()` displays a value on the terminal.
- `return` gives the value back to the caller so it can be stored or used in another expression.

## Different Ways of Writing Functions

Today I learned that JavaScript has three common ways to write functions:

1. **Function Declaration**

```javascript
function greet(name) {
    return "Hello " + name;
}
```

2. **Function Expression**

```javascript
const greet = function(name) {
    return "Hello " + name;
};
```

3. **Arrow Function**

```javascript
const greet = (name) => {
    return "Hello " + name;
};
```

I learned that all three can be used to write functions, but they have some differences.

A **function declaration** is the most common way to write a function. It is **hoisted**, so it can be called even before it is written in the file.

A **function expression** stores a function inside a variable. Since it is stored in a variable, it cannot be used before the variable is initialized.

An **arrow function** is a shorter way of writing a function. It was introduced to reduce the amount of code we write for small functions. It also behaves differently with `this`

 I understood that function declarations are easier to read, while arrow functions are useful for writing short and simple functions.


## Hoisting and Temporal Dead Zone(TDZ)

- Js executes a program in two phases:

    - **Creation Phase** -Js scans the entire file all finds all the variables ,fucntion declaration and creates memory for them .
    - **Execution Phase** - Js executes the code line by line .

So **hoisting** is Js process of finding declarations and creating memory for them before the code starts executing.

**TDZ**- It is the period of time between entering a scope and the moment the variables declaration line is actually executed .

*I also learned why the Temporal Dead Zone (TDZ) exists.*

When we use `let` or `const`, JavaScript creates memory for the variable during the creation phase, but the variable is not ready to use until the execution reaches its declaration. If I try to use it before that, JavaScript throws a `ReferenceError`.

- The main reason for the TDZ is to *prevent bugs*.
- `var` is initialized with `undefined` during the creation phase.
- `let` and `const` are also hoisted, but they stay `uninitialized` until their declaration is executed.
